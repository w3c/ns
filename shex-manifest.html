This document describes the ShEx Manifest Vocabulary and Term definitions used for writing manifests of Shape Expressions [[shex-semantics]] examples and tests. This document provides the RDFS [[RDF-SCHEMA]] vocabulary definition and a description of the JSON-LD context definition for use with writing manifests in JSON-LD or YAML-LD.

Alternate versions of the vocabulary definition exist in Turtle and JSON-LD, which also includes the @context a JSON-LD or YAML-LD manifest references.

Introduction

This document describes the RDFS vocabulary used to write ShEx manifests -- ordered lists of entries, each a schema, some data and a query map, with the outcome expected of validating them [[shex-semantics]] [[shape-map]] -- along with the JSON-LD Context that makes a JSON or YAML manifest an RDF graph. Test suites and the example collections of ShEx implementations write their manifests with it.

This specification makes use of the following namespaces:

shexMan:
http://www.w3.org/ns/shex-manifest#
shex:
http://www.w3.org/ns/shex#
rdf:
http://www.w3.org/1999/02/22-rdf-syntax-ns#
rdfs:
http://www.w3.org/2000/01/rdf-schema#
xsd:
http://www.w3.org/2001/XMLSchema#

Class Definitions

The following are class definitions in the shexMan namespace:

Entry Entry §

One validation and the outcome expected of it: a schema, the data to validate, and a query map (or one node and one shape) saying which nodes are validated against which shapes.
Manifest Manifest §

An ordered collection of entries: the examples a ShEx implementation offers, or the tests of a test suite.

Property Definitions

The following are property definitions in the shexMan namespace:

data data §

The data the entry validates. A literal is the data's text; an IRI (written with the term dataURL) is the document that holds it. Several values are the documents of one graph.

rdfs:domain
shexMan:Entry
dataLabel data label §

What to call the entry's data when presenting it to a person.

rdfs:range
xsd:string
rdfs:domain
shexMan:Entry
entries entries §

The entries of a manifest, in order.

rdfs:range
shexMan:Entry
rdfs:domain
shexMan:Manifest
name name §

A name for the entry, unique within its manifest.

rdfs:range
xsd:string
rdfs:domain
shexMan:Entry
queryMap query map §

The entry's query map, pairing node selectors with shapes. A literal is the map in ShapeMap syntax; an IRI (written with the term queryMapURL) is the document that holds it. An entry with one node and one shape may write them as shex:node and shex:shape instead.

rdfs:domain
shexMan:Entry
queryMapLabel query map label §

What to call the entry's query map when presenting it to a person.

rdfs:range
xsd:string
rdfs:domain
shexMan:Entry
schema schema §

The entry's schema. A literal is the schema's text; an IRI (written with the term schemaURL) is the document that holds it.

rdfs:domain
shexMan:Entry
schemaLabel schema label §

What to call the entry's schema when presenting it to a person. Entries with one schema usually share its label.

rdfs:range
xsd:string
rdfs:domain
shexMan:Entry
